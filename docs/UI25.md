# UI25 behavior and validation

Version: `2.0.0~ui25`.

Manual USB reset is distinct from automatic outage recovery: all relevant storage
must already be unmounted, process/namespace isolation must pass, and the disk is
left unmounted. The server checks before side effects. Monitoring is not paused
for this action. Linux leaf-device reset is available when individual port control
is unsupported and the selected storage-only USB device can be isolated; shared
hubs/controllers and multi-disk devices are not reset.

A physically observed reconnect returned on the controller's paired USB2/USB3
port with a new bus/device address. Return verification now rebinds only after
UUID, serial, VID:PID, controller and recorded companion-port checks pass. A
separate observed `/proc/<pid>/mountinfo` EINVAL race is ignored only when a kernel
pidfd proves the process exited. Live or unclassified inspection failures still
refuse the operation. An older descriptor refusal remains unexplained; these
changes do not claim to identify its cause.

Boot startup is opt-in per container with separate explicit disk/image
prerequisites, recorded in `/etc/usb-storage-watch/boot-start.json`. The systemd
boot timer runs independently of monitoring. It waits for Docker/storage and
operation ownership, verifies prerequisite mounts, then starts once per host boot.
Receipts under `/var/lib/usb-storage-watch/boot-start` preserve action intent,
verification, cancellation and uncertainty across coordinator restarts. Containers
using Docker-managed restart policies cannot enable this option until the user
sets that policy to `no`. Existing recovery selections remain unchanged.

Regression coverage includes repeated UI24 recovery/incident cleanup, paired-port
and device-address changes, mounted/active-user refusals, unsupported device reset,
startup ordering, explicit second-disk dependencies, monitoring off, later manual
stops, interrupted actions and competing operation locks. These are simulated
checks. Current packaged UI checks exercise 320, 390, 768 and 1440 pixel widths;
isolated installer checks do not operate real services or boot a VM.

Physical tests on one test host verify a guarded port reconnect and boot
coordinator startup with existing selected disk/image mounts. This is not a
distribution/hardware support matrix or a real reboot test. Leaf-device reset
behind external hubs and electrical power removal have not been physically
verified. No electrical power-cycle claim is made. The earlier UI24 successful
physical repeated-recovery evidence is retained; UI25's repeated recovery checks
are simulated rather than a new disruptive outage series.
