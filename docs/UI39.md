# UI39 — storage verification before manual app starts

Manual Start/Restart now verifies the physical filesystems and virtual images in
both saved startup and recovery selections. Retained choices with an automatic
switch off still describe required storage for an explicit manual start. No
requirements are inferred from container names or bind mappings.

The shared dashboard/Companion backend takes sorted existing recovery locks and
the pinned container lock, rechecks configuration and operation restrictions, and
uses the existing UUID/ext4/mount and loop-image backing verifiers before sending
a Docker command. Refusals preserve manual-stop holds. Already-running Start
also verifies storage before releasing a deliberate-stop hold. No implicit mount,
monitoring enablement, image option change or command replay is introduced.

Stop keeps its existing restrictions and has no new storage-readiness gate.
Healthy selected storage is usable with monitoring off; apps with no configured
storage choices remain usable. Unreadable saved configuration refuses Start/
Restart because dependencies cannot be established; Stop retains its old behavior.

Validation uses simulated storage/Docker, real authenticated routes, receipts and
locks, including repeated safe unmount worker IPC. No new physical outage test is
claimed. Companion 0.2.6 remains byte-for-byte unchanged. Zorin still needs local
compatibility/conflict preflight. The historical Companion HTTP 503 cause and
Erugo application-file verification remain unresolved.

Before installing/upgrading, verify no recovery/storage operation is active and
privately back up configuration/state plus the prior package. UI38 rollback retains
configuration but also restores its manual-start readiness gap; do not use manual
Start/Restart on unavailable storage after a rollback. Do not overwrite newer
incident receipts with older backups.
