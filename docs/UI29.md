# UI29 image selectors and unavailable apps

Version `2.0.0~ui29`, local test release.

Nested virtual-image sections use a darker background, indentation and a separate
border; physical-drive backgrounds are unchanged. Each section collapses
independently. The heading shows the selected count and names even when closed.
Expansion survives edits, application refreshes and browser reloads using local
browser preferences (session memory remains when browser storage is restricted).
Collapse never modifies app selections. Both panels explain: “Select only the
virtual images this app needs. Otherwise, leave them unselected.” The recovery
panel is named **Drive failure & recovery**.

## Saved identities

Live apps are full cards. Saved identities absent from a successful complete Docker
inventory appear compactly under **Unavailable apps**. Different IDs sharing a
name remain separate. Docker failures or malformed/partial discovery mean unknown
status; they do not authorize removal or reconnection.

- **Reconnect to an existing container** requires selecting an exact current ID,
  with no default chosen by name, then reviewing and confirming both identities.
  A destination with existing saved settings is refused rather than overwritten
  or merged. Drive/image choices and per-app options are retained, with computer
  startup and recovery explicitly **off**. Review and enable them on the destination
  card using the existing policy/Compose safeguards. Reconnection itself performs
  no Docker policy, container runtime, mount or service operation.
- **Remove saved entry** requires review and confirmation. It removes only that
  identity's boot, recovery and retained inactive configuration references. Docker
  containers, storage contents and all historical recovery/policy records remain.

The authenticated broker validates inventory and configuration revisions again
before writing. Existing storage/container/configuration locks prevent competing
operations. Only fixed configuration paths are writable; previews cannot supply
file paths. Changed documents are privately backed up under the state root's
`app-entry-backups`. A durable journal restores exact pre-change documents after
interruption or failure, refusing to overwrite subsequent independent edits. Lost
responses are refreshed, never automatically replayed.

No automatic stale-ID cleanup or name-based reassignment is introduced. A saved
ID can remain intentionally inactive. Legacy entries without a full pinned ID
need administrator identity review; they cannot be guessed from a name.

## Verification

Focused isolated tests cover old/new IDs sharing a name, inactive selections,
protected destinations, explicit reconnect with automatic options off, removal,
authentication/CSRF, stale previews, locks, inventory failures, private backup,
rollback and retained history. Browser journeys use synthetic APIs at desktop,
tablet and narrow-mobile sizes. Existing app save/failure, boot and repeated
recovery regressions remain separate from physical tests.

Installation must preserve current live app settings and runtime. Removal of any
host-specific obsolete reference requires fresh successful inventory and a
verified private backup, followed by exact configuration readback. No new hardware
or reboot verification is claimed for this interface release.
