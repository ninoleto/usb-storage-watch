# UI33 — repeated safe unmount correction

UI32 could refuse a later reviewed unmount after an earlier intentional unmount,
remount and manual app start. Its admission check acquired `manual-unmount.lock`,
then interpreted that same lock together with the retained earlier receipt as a
different operation in progress. This happened before writing new intent,
stopping apps or launching the storage worker.

The broker now passes its held lock descriptor to its own admission checks. The
descriptor must match that drive's lock file. Only that ownership is excluded;
other drives, active recovery incidents and concurrent app operations still block.
There is no client-supplied exemption. Completed receipts remain durable startup
holds, not evidence by themselves of live work. Inherited worker/command locks
remain authoritative even if a receipt already records a terminal phase.

No receipts are deleted or migrated. Explicit manual Start/Restart still releases
only the corresponding app hold. Pending boot startup, shared recovery suppression,
selected identities/images and the ordinary busy-storage checks are unchanged.

The confirmation keeps progress visible and disables duplicates while waiting.
After refusal or an uncertain response, Confirm stays disabled and the dialog
explains how to close it, inspect status and obtain a fresh review. No command is
automatically retried and consumed confirmation tokens are never reused.

## Validation scope

- Reproduce the earlier unmount/remount/manual-start sequence, then add another
  ordinary-folder app with no images before the next review.
- Use the authenticated Flask routes and production broker, `Worker` subprocess,
  `_manual` entry point, inherited flock descriptors, JSON result and unmount
  ordering. Docker/storage observations and command effects use isolated fixtures;
  no host app or filesystem is stopped/unmounted by these tests.
- Cover active, completed, failed and orphaned receipts, shared dependencies,
  unrelated apps, genuine concurrent workers, duplicate confirmation, busy-storage
  refusal, stale settings, boot holds and repeated recovery.
- Check pending/refused/uncertain/successful UI states at 320/768/1440px; preserve
  the UI32 card locks and selector appearance.

This release requires a fresh user-controlled manual acceptance test. Installing
it must not itself repeat an unmount, clear an intent receipt or restart apps.
Rollback to UI32 retains configuration but reintroduces the repeated-unmount bug.
