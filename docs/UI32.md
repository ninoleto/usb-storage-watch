# UI32 — safe manual unmount and selector contrast

Test release `2.0.0~ui32`. No reboot or hardware-reset feature is added.

Enabled dropdown fields retain their dark blue background and use a 2 px white
border and white down arrow. Padding compensates for the wider border. Disabled
fields remain subdued; keyboard focus and touch pickers are retained. The native
arrow is a local SVG served under the existing content security policy.

## Unmount safely

The dashboard's existing confirmation now reviews apps actively selected under
**Restart after a drive problem** for this drive, with their pinned container IDs
and selected virtual images. Retained inactive choices do not grant permission
to stop an app. Ordinary external folders work without images. Bind detection
never adds apps to the stop list.

Confirmation belongs to the authenticated session, expires after five minutes,
and is consumed once. Changes to app identity/execution, filesystem mount identity,
settings or boot prerequisites require another review. Missing/unverifiable apps
refuse the operation. Existing container locks serialize conflicting app controls,
policy/identity confirmations and settings. The affected cards show a readable
safe-unmount notice; read-only app status and unrelated apps remain available.

Selected running apps receive one stop request each, followed by authoritative
Docker readback, including after a lost acknowledgement. Already-stopped apps do
not receive a stop. A stop failure identifies the app and aborts before monitoring
or storage changes. Earlier completed stops are reported; no restart is attempted.
All selected apps are verified again before the existing storage worker runs.
The worker retains identity, descriptor/busy-user and configured-image checks,
ordinary image-before-main unmount, and physical mount readback. Unrelated storage
users still refuse unmount. No forced/lazy unmount or filesystem content edits.

The existing monitoring behavior remains: successful intentional unmount stops
and disables that drive's monitor; a storage failure follows the existing paused/
unchanged-storage handling. External unmount detection is unchanged. The legacy
Companion unmount action now directs users to the dashboard review; its old token
cannot silently authorize stopping dependent apps.

Private same-boot receipts keep affected apps stopped across shared-drive recovery
and cancel pending startup for the deliberately unmounted drive. They change no
saved startup/recovery selections. Manual **Mount** does not clear app stop intent
or start apps. Use **Start app** explicitly after storage is ready; a verified
manual Start/Restart clears that app's hold. The next computer boot uses the saved
startup configuration normally. A refusal before action preserves monitoring;
a partial stop/storage failure retains the deliberate startup hold and reports it.

App locks are inherited by the storage worker and its command children. An
interrupted request is not replayed. A durable intent alone does not leave UI
controls disabled forever; live operation locks determine that temporary state.
Automatic outage records and incident-scoped cleanup budgets are unchanged.

## Verification and limits

Focused tests use isolated Docker/storage boundaries and real locks/receipts:
stop/unmount order, already stopped apps, stop failure/lost acknowledgement,
identity/execution/configuration changes, shared dependencies, competing commands,
worker lock inheritance, boot suppression and repeated recovery. Browser tests
exercise mobile/tablet/desktop layouts, selector states, review/cancel/refusal,
active app locks and draft preservation under the production CSP.

Installation verification checks source/static bytes, saved settings, running app
start times, boot receipts, services, localhost and this host's own HTTPS address.
These checks do not claim a new physical unmount/recovery, reboot, application file
integrity test or startup-email delivery. Keep the private pre-upgrade configuration/
state archive and prior package for rollback; package rollback alone preserves
settings but an older version does not enforce UI32 manual-unmount receipts.
