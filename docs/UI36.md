# UI36 — outcome history and saved app settings

Completed history uses the recorded outcome time for its main timestamp and
newest-first ordering, across drives and UTC offsets. Outage start is displayed
separately. A return-timeout failure and later successful recovery remain separate
records. Original cached event timestamps and incident/receipt files are retained;
an additive history metadata table supplies presentation times. Existing archives
and exact cached outcome timestamps can populate that metadata. Missing outcome
times are not invented. The existing history retention limit is unchanged.

App headers show Startup enabled/off and Recovery enabled/off from verified saved
settings, not unsaved edits. Missing or failed settings reads show unknown. These
indicators remain separate from Running/Stopped and active recovery warnings, and
wrap on narrow screens. Drafts and collapse state survive polling.

Focused regression coverage includes late recovery after timeout, archive/cache
migration, unchanged evidence, timezone ordering, retention, and ordinary actions.
Browser fixtures cover mobile, tablet and desktop layouts, collapsed cards, drafts,
external saved changes, missing/failed/partial settings, unavailable identities,
and active recovery restrictions. No recovery or startup engine behavior changes.

A local install is a test candidate. A fresh physical timeout/reconnect, existing
file access through each dependent app, and connected-storage reboot acceptance
are required before a verified source checkpoint or subsequent integration work.

Rollback to the preceding UI35 package retains compatible configuration and
incident state; the additional history metadata table is ignored by that version.
Only downgrade while recovery/maintenance operations are inactive. Do not restore
stale state or delete receipts. UI35 restores its older history display behavior.
