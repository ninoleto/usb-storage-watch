# UI26 guided container setup

Version: `2.0.0~ui26`, test release. Existing USB and storage-recovery algorithms
are unchanged. Images remain optional: an application may stay on the SSD with
ordinary folders bind-mounted from the selected external filesystem. A directory
at the mountpoint alone never satisfies the existing UUID/filesystem checks.

Docker & Applications displays each detected container's current restart policy,
identifiable manager, saved boot/recovery prerequisites and unresolved conflicts.
**Review Storage Watch management** explains the change and prepares a five-minute
preview for that exact container ID. **Confirm policy setup** applies only that
preview, with the existing login and CSRF checks. It does not enable boot/recovery
choices, substitute a container by name, or recreate/restart the container.

The live Docker update contains only `RestartPolicy`. An already-correct `no`
policy causes no update. Readback verifies the policy, unchanged container
execution, ports, environment, images, mount mappings and other configuration.
The original policy, including its retry count, is retained privately at
`/var/lib/usb-storage-watch/docker-setup/<container-id>/record.json`.
An uncertain response is read back without repeating the update. Unresolved
outcomes block another setup attempt until their record is reviewed.

For Docker Compose, automatic editing requires:

- Identified project, selected service and ordered local source files from the
  container labels, reproduced with the system Compose plugin and project owner.
- An effective service hash matching the container's creation hash, or the exact
  previously verified managed hash. Unknown original interpolation environments
  therefore produce instructions instead of a guessed edit.
- Regular files inside the recorded project, no symlink/hardlink ambiguity, and
  writes restricted to root/project owner or a proven owner-private Unix group.
- Ordinary YAML mappings without duplicate keys, anchors, aliases, custom merge
  tags, include/extends or conflicting deploy restart policies. Unsupported
  sources receive precise manual-review guidance; this is not a universal Compose
  editor. Explicit env-file paths and project `.env` are included in the review.

The preview shows the selected service, ordered files and exact restart-field
replacement/insertion in the last file defining that service. Comments and other
source text are preserved. The original is backed up privately before an atomic
replacement. Full effective models, including all overrides and services, are
compared in memory: only the selected restart policy may differ. Model contents,
environment values and Compose stderr are never returned to the browser or logs.
No Compose up, restart, build or pull command is used. File/env changes after a
preview invalidate it. Later source drift or a conflicting live policy is shown
on refresh, and management is not reported as fully verified.

If Docker refuses an update, the app restores only its exact Compose edit after
proving the live policy stayed unchanged. It never overwrites someone else's
subsequent edit. Private backups and unresolved records are retained for review.
External managers such as Portainer, Swarm and Kubernetes receive appropriate
instructions or unsupported-ownership explanations; no task or stack is modified.
When no manager can be identified, live-policy verification is explicitly separate
from unverified external startup ownership (for example a systemd wrapper).

To restore a prior policy, first disable this app's boot/recovery selections for
the container, review its original policy record, and use Docker's policy-only
update for the exact ID. For `on-failure` include the saved retry count. Review the
private Compose backup against current files and restore only the selected policy
field; never blindly replace a file containing later unrelated edits. Validate
with the original file order/project/environment and verify the live policy.

**Start automatically when the computer starts** still waits for selected disks
and any selected images. Disk-recovery restarts are configured independently.
This feature manages computer startup and storage recovery; it is **not a general
application-crash restart watchdog**.

Docker documents policy updates on running containers without requiring a restart
in [container update](https://docs.docker.com/reference/cli/docker/container/update/).
The ordered override/effective-config behavior follows
[Compose file merging](https://docs.docker.com/compose/how-tos/multiple-compose-files/merge/).

Validation distinguishes simulated Docker mutations and real Compose validation
in temporary projects from installed-host checks. Existing UI25 physical reset,
reboot and unplug/reconnect evidence remains applicable to unchanged recovery
code; no new physical recovery result is claimed by this release.
